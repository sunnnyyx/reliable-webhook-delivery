# Milestone 10 security review

Reviewed locally on 2026-10-16. This is a source/test review and known-vulnerability scan, not an independent penetration test or production certification. No hosted environment exists.

| Boundary | Reviewed implementation and evidence | Remaining limits |
| --- | --- | --- |
| Tenant authorization | API requires one bearer header and checks active keys/tenants for each operation. Repository queries use tenant IDs from authentication, composite foreign keys and tenant-bound cursors. Integration tests cover cross-tenant access, revocation, lifecycle mutations and concurrency. | Tenant/key provisioning stays administrative CLI; production ingress authentication abuse limits and operator access control need deployment configuration. |
| Endpoint secrets | AES-GCM with contextual AAD; creation/rotation return plaintext once; signing after commit loads active overlapping keys. Unit/integration rotation and authenticated decryption tests. | Master-key backup/rotation and production secret injection remain operational work; no plaintext logging is permitted. |
| Outbound SSRF | Explicit HTTPS/443 policy; all resolved addresses vetted, numeric direct dial prevents second resolution; blocked special ranges, no redirects/proxies/reuse, TLS verification/SNI and bounded responses/time. Local exception is one exact configured URL and is rejected in production. Network-policy tests include mixed/private DNS and numeric forms. | Process policy is defense in depth; production egress/firewall rules remain required. Registry exclusions must be maintained. DNS answers and certificates can change. No unrestricted network penetration scan was performed. |
| HTTP/JSON | Header/body/time bounds; valid UTF-8, unique JSON keys, depth limit, exact event type/data contract and immutable byte hashing. Retryable responses preserve idempotency guidance. | Payloads can contain sensitive tenant data and are intentionally visible in authenticated event detail; production retention/encryption/storage ACLs must be operated. |
| Browser console | Loopback development-only BFF; opaque HttpOnly/SameSite session, exact Host/Origin and CSRF checks, Fetch Metadata, no browser credential storage, fixed upstream/no redirect/proxy, route/body/response/session bounds. CSP and textContent rendering, no-store/no-referrer and one-time secret clearing. Unit/race and real-console smoke evidence in milestone 9. | Local HTTP cookie has no Secure flag. Machine trust, same-host cookie scope, single-process memory sessions and in-flight requests finishing after logout are explicit. Hosted identity/TLS and shared sessions are not implemented. |
| Durable work | Transactional idempotency/fan-out, immutable snapshots, fenced completion, endpoint-first recovery and finite budgets. New admission count stops only after enough rows to decide rejection; exact-capacity and oversize-fan-out integration test added. | At-least-once HTTP remains possible. Acknowledgment is not proof of exactly-once business effects; receiver local transaction/outbox is a separate boundary. |
| Telemetry | Loopback metrics/health; bounded dimensions, no payload/key/URL/baggage attributes, trusted bounded optional collector exporter; tracing not forwarded to receivers. Logs contain IDs and sanitized codes. | Private logs/traces can contain tenant/event IDs and must receive production access/retention controls. Diagnostics are best effort, not audit totals. |
| Database/query resources | Parameterized application SQL; bounded pagination, pool settings and request contexts; new tenant/endpoint due index plus statement-time cutoff avoid unrelated-work scans. Benchmark SQL seeds only generated disposable schemas after validating local development URL/user/database/port/profile. | Index migration takes a normal PostgreSQL index-build lock; schedule a maintenance migration for an existing large deployment. Global queue snapshots still aggregate history and need measured scaling/rollups later. DB ACLs/backups/restores/retention jobs are not established by local tests. |

## Dependency check

Ran the official Go `govulncheck` v1.8.0 source/symbol scan across `./...` using Go 1.27.2. Exit code was zero; no finding messages were returned. The scanner queried `https://vuln.go.dev`, whose recorded database modification time was 2026-10-08T22:31:09Z. The 255 OSV advisory records in its raw protocol stream are database input, not 255 project findings. [Raw output](../benchmarks/security/govulncheck.json), [summary](../benchmarks/security/summary.json), and tool download stderr are retained. The scan sends public dependency/module identity information to the Go module/vulnerability services; no project payloads or credentials are included in these result artifacts.

Reproduce with `make security-check` (requires network; pins the scanner tool without adding it to the application go.mod). Also run `go mod verify`. A clean result only covers known database entries and scanner reachability analysis at that time; it cannot rule out unknown flaws, configuration errors, application logic bugs or future advisories.

Primary references: [Go vulnerability management](https://go.dev/doc/security/vuln/) and [govulncheck documentation](https://pkg.go.dev/golang.org/x/vuln@v1.8.0/cmd/govulncheck).

## Review outcome

The observed resource hardening changes are the endpoint due-query index/range predicate and bounded admission count, described in the [benchmark report](../benchmarks/README.md). No authorization or delivery guarantees were relaxed for speed. Production TLS, private dependencies, backups/restores, least-privilege runtime users, CI and image/dependency checks belong to milestone 11; no deployed security posture is claimed here.
